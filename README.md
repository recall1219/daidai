# 呆呆面板 Magisk 模块 v3.4.4 — 修改说明

本次修改针对 `customize.sh`（模块安装脚本），解决"下载失败后无法再次安装"的问题。模块其余文件（二进制、前端、刷入脚本、`module.prop`）均未改动。

## 修改背景

- 现象：手机（KernelSU / Android 16）安装 v3.4.4 模块时失败，报错：

  ```
  检测到已有面板数据
  正在保留用户数据...
  ! 数据备份目录为空，可能复制失败，已中止安装以保护数据
  Error: Failed to install module script
  ```

- 根因：首次安装若在中途（如 rootfs 下载失败）中断，只会留下一个**空的** `Dumb-Panel` 数据目录。重装时脚本检测到目录存在就走备份流程，而 `cp -rf "目录/."` 的写法在部分 Android toybox 上会静默复制成空，`ls -1` 统计为 0，随即 `abort` 中止安装。其结果是：一次下载失败会让用户此后即使网络恢复也**永久无法重装**。

- 目标：取消"因数据判断而中止安装"的行为，杜绝卡死重装；同时不丢失用户数据。

## 修改内容

所有修改均在 `customize.sh` 的数据保留/恢复相关逻辑中，原则为"异常只警告、不阻断，数据尽力保留"。

1. **空数据目录直接放行**
   备份前先探测源数据目录是否真的含有内容（含隐藏文件）。若为空，判定为无数据需要保留，直接继续安装，不再触发备份失败中止。

2. **备份方式改为逐项复制，失败不中止**
   将 `cp -rf "目录/."` 改为逐项复制（与脚本自身的数据回填逻辑一致），规避部分 toybox 上复制成空的问题。任一文件复制失败仅打印警告，不再 `abort`。

3. **备份全失败时整体保留旧数据**
   若逐项复制后备份目录仍为空，用 `mv` 将整个旧数据目录移动到持久化救援目录 `/data/adb/daidai-panel/rescue-Dumb-Panel-<时间戳>`（同分区移动为原子重命名，几乎不会失败），并把它设为回填源，安装完成后自动恢复数据，用户无感。

4. **目录创建失败不再阻断**
   `mkdir -p` 持久化目录 / 备份目录失败时，跳过自动备份并继续安装，不再中止。

5. **清 rootfs 前的兜底检查改为非阻断**
   原本"面板数据存在但未成功备份则 abort"的检查，改为把旧数据 mv 到救援目录后继续安装。

6. **数据回填失败不再阻断且不丢数据**
   回填时若某个文件复制失败，仅警告并保留备份目录供手动找回；只有全部恢复成功才删除备份，避免部分失败导致数据丢失。

7. **更新过时注释**
   将描述旧"备份失败中止"行为的注释更新为新的"数据保护不阻断安装"行为。

## 修改后效果

- 数据/备份相关的 `abort` 全部移除；仅保留架构不符、环境异常等真正需要中止的检查（这些在网络恢复后可正常重试）。
- 下载失败后再次安装不再卡死；用户旧数据在各类异常下均被保留或自动恢复。
